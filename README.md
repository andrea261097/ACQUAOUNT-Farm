# ACQUAOUNT-FARM'S IRRIGATION MODEL – First Run Guide

## Repository structure

The repository is organized into input, configuration, and output folders. Input data include crop parameters, soil characteristics, irrigation system settings, soil moisture sensor readings, and climate data (both past observations and short-term forecasts). Outputs are automatically generated by the model at the end of each run and stored in dedicated CSV files.

## Requirements

Before running the model for the first time, make sure that:

* All required input files are available and correctly formatted as the files in the example
* File paths inside configuration files are consistent with the local folder structure
* Input data units match the expected units described in the variable documentation

The model is designed to be run sequentially; outputs from previous runs may be reused to improve calibration and consistency over time.

## Software

R (>= 4.0) with the packages loaded at the top of `Irrigation_model_for_paper/ACQUAOUNT_farm.R`: tictoc, readxl, units, lubridate, dplyr, randomForest, outliers, soilDB, aqp, ranger, parallel, jsonlite. Run the script with the working directory set to the `Irrigation_model_for_paper` folder.

## Configuration file (mandatory)

JSON configuration file (`config.input.json`). This file contains all farm-specific parameters provided by the user, including crop type, growing season dates, planting geometry, soil texture and hydraulic properties, climate zone, geographic location, irrigation method, irrigation system characteristics, and sensor layout.

Units of the irrigation-system parameters: `d_rate` (drip) and `s_rate` (sprinkler) are flow rates in **L h⁻¹ per emitter / per nozzle**; `d_spacing` and `d_depth` in m; `w_length` is the **total length of the drip lines** in m (the number of emitters is `w_length / d_spacing`); `n_emitter` (sprinkler) is the number of nozzles; `Area_crop` in m²; soil texture, organic matter and soil-water thresholds in %; `Ks` in cm h⁻¹; `Pb` in g cm⁻³.

All parameters must be filled before the first run. If user-defined soil hydraulic thresholds (saturation, field capacity, wilting point) are provided, the model will use them directly; otherwise, internally derived values may be used depending on the setup.

## Crop parameters

Crop-specific information (crop coefficients, phenological stages, rooting depth, and irrigation-related parameters) is stored in the crop table (`Input_data/crop_data/crop_table_REVIEWED.csv`). The crop name defined in the JSON configuration file must exactly match one of the crop names in this table.

## Climate and sensor data

The model requires hourly climate data for the past 168 hours and for the following 168 hours. Past data typically come from sensors or local weather stations, while future data are usually provided by a weather forecast API. Required variables include air temperature, precipitation, solar radiation, relative humidity, wind speed, dates, and hours.

Soil moisture sensor data must be provided as a matrix where each column represents a sensor installed at a different depth. The number of sensors must be consistent with the sensor spacing declared in the configuration file.
Past irrigation data coming from the water meter must be structured in the same format of the climate data (i.e., an array of 168 values, expressing the volume released by the irrigation system at hourly scale)

## First execution

To run the model for the first time:

1. Prepare and validate the `config.input.json` file
2. Place all required input files in their corresponding folders
3. Initialize the files 'kc_correction.csv' to 1 and 'SM_extremes_previous_run.csv' with the minimum and maximum soil moisture values recorded by the sensor.
4. Execute the main model script according to your local setup (e.g. R environment or automated pipeline)

During the first run, the model initializes internal variables, computes soil water balance, estimates crop water requirements, and generates irrigation suggestions without relying on previous calibration data.

## Outputs

After a successful run, the model produces:

* Hourly irrigation suggestions and soil moisture estimates
* Daily aggregated irrigation volumes and soil moisture
* Key irrigation dates associated with different water stress levels
* Updated soil moisture extremes and crop coefficient correction factors, which are saved and reused in subsequent runs

All outputs are exported as CSV files and can be directly used for visualization, decision support tools, or further analysis.

## Notes on subsequent runs

From the second run onward, the model can exploit information saved from previous simulations (e.g. soil moisture extremes and kc correction factors) to improve robustness and temporal consistency. For this reason, output files generated by the model should not be deleted between runs unless a full reset is explicitly required.
